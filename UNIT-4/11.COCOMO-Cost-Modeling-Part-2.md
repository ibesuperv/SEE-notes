## 1. The COCOMO II Reuse Model

The reuse model calculates the effort needed to integrate pre-existing white-box reusable code components or automatically generated code.

### 1.1 Black-Box vs. White-Box Reuse

- **Black-Box Reuse:** Code is integrated without making changes (e.g., standard libraries). Development effort is assumed to be **zero**, and its size is ignored in effort calculations.
- **White-Box Reuse:** Reused code must be adapted, understood, and modified to integrate with new code.

### 1.2 Equivalent Source Lines of Code (ESLOC)

To calculate effort for white-box reuse, the code size is converted to **ESLOC (Equivalent Source Lines of Code)** using the following formula:

$$\text{ESLOC} = \text{ASLOC} \times \left(1 - \frac{\text{AT}}{100}\right) \times \text{AAM}$$

Where:

- **ASLOC:** The number of lines of code in the reused components that need changes.
- **AT:** The percentage of reused code that can be modified automatically (reducing manual adaptation effort).
- **AAM (Adaptation Adjustment Multiplier):** Adjusts the estimate based on three factors:
  $$\text{AAM} = \text{AA} + \text{SU} + \text{AAF}$$
  _ **AA (Assessment Factor):** The effort spent searching for and evaluating the component for reuse (ranges from **0 to 8**).
  _ **SU (Software Understanding):** The effort required to understand the code (ranges from **10** for clean, object-oriented code to **50** for complex, unstructured code). \* **AAF (Adaptation Adjustment Factor):** The effort required to make design, code, and integration changes.

Once ESLOC is calculated, it is plugged into the effort formula as the **Size** parameter:
$$\text{Effort} = A \times \text{ESLOC}^B \times M$$

---

### 1.3 Solved Numerical Example: ESLOC & Reuse Effort

**Problem:** A project is reusing **20,000 lines of code (ASLOC)** from an older system. **20% of the modifications can be done automatically (AT)**.
The Adaptation Adjustment Multiplier (AAM) factors are: $\text{AA} = 4$, $\text{SU} = 20$, and $\text{AAF} = 16$.
Calculate the **ESLOC** and the estimated effort if $A = 2.94$, $B = 1.10$, and $M = 1.0$.

- **Given:**
  - $\text{ASLOC} = 20,000$ (or 20 KSLOC)
  - $\text{AT} = 20$
  - $\text{AAM} = \frac{\text{AA} + \text{SU} + \text{AAF}}{100} = \frac{4 + 20 + 16}{100} = \frac{40}{100} = 0.40$

- **Calculation for ESLOC:**
  $$\text{ESLOC} = 20,000 \times \left(1 - \frac{20}{100}\right) \times 0.40$$
  $$\text{ESLOC} = 20,000 \times 0.80 \times 0.40 = 16,000 \times 0.40 = \mathbf{6,400 \text{ LOC}} \quad (6.4 \text{ KSLOC})$$

- **Calculation for Effort:**
  $$\text{Effort} = 2.94 \times (6.4)^{1.10} \times 1.0$$
- First calculate $6.4^{1.10}$:
  $$6.4^{1.10} \approx 7.64$$
- Multiply factors:
  $$\text{Effort} = 2.94 \times 7.64 \times 1.0 \approx \mathbf{22.46 \text{ Person-Months}}$$

## 2. The Post-Architecture Level

This model is the most detailed COCOMO II submodel. It is applied after the initial software architecture has been designed.

### 2.1 Total Size Calculation

$$\text{Total Size} = \text{SLOC (New Code)} + \text{ESLOC (Reused Code)} + \text{Modified Code (Requirements Volatility)}$$

### 2.2 Exponent B Calculation (Scale Factors)

Unlike the early design model where $B$ is a generic range, the Post-Architecture model calculates $B$ using **5 scale factors** rated on a **0 (Extra-High / Excellent)** to **5 (Very Low / Poor)** scale:

1.  **Precedentedness (PREC):** Experience of the organization in this specific domain.
2.  **Development Flexibility (FLEX):** Degree of flexibility allowed by the client.
3.  **Architecture/Risk Resolution (RESL):** Depth of risk analysis carried out.
4.  **Team Cohesion (TEAM):** How well the team works together.
5.  **Process Maturity (PMAT):** The organization's CMM process maturity rating.

$$\text{Exponent B} = 1.01 + \frac{\sum(\text{Scale Factor Ratings})}{100}$$

---

### 2.3 Solved Numerical Example: Exponent B

**Problem:** An organization has the following scale factor ratings for a new project:

- Precedentedness (PREC): Low (rating = 4)
- Development Flexibility (FLEX): Very High (rating = 1)
- Architecture/Risk Resolution (RESL): Very Low (rating = 5)
- Team Cohesion (TEAM): Nominal (rating = 3)
- Process Maturity (PMAT): Nominal (rating = 3)
  Calculate the Exponent $B$.

- **Calculation:**
  $$\sum(\text{Ratings}) = 4 + 1 + 5 + 3 + 3 = 16$$
  $$\text{Exponent B} = 1.01 + \frac{16}{100} = 1.01 + 0.16 = \mathbf{1.17}$$

## 3. Project Duration and Staffing

### 3.1 Time to Develop (TDEV) Formula

COCOMO II estimates the nominal calendar time (in months) required to complete a project using this equation:

$$\text{TDEV} = 3 \times (\text{PM})^{(0.33 + 0.2 \times (B - 1.01))}$$

Where:

- **PM:** Effort calculated from the COCOMO model (Person-Months).
- **B:** The complexity exponent calculated above.

---

### 3.2 Solved Numerical Example: TDEV Calculation

**Problem:** A project is estimated to require **80 Person-Months (PM)** of effort. The complexity exponent $B$ has been calculated as **1.16**.
Calculate the estimated nominal project duration in months.

- **Given:**
  - $\text{PM} = 80$
  - $B = 1.16$

- **Calculation:**
- First calculate the exponent term:
  $$\text{Exponent} = 0.33 + 0.2 \times (1.16 - 1.01) = 0.33 + 0.2 \times (0.15) = 0.33 + 0.03 = 0.36$$
- Now apply the formula:
  $$\text{TDEV} = 3 \times (80)^{0.36}$$
- Calculate $80^{0.36}$:
  $$80^{0.36} \approx 4.84$$
- Multiply:
  $$\text{TDEV} = 3 \times 4.84 \approx \mathbf{14.52 \text{ Months}}$$

---

### 3.3 Schedule Compression & Brooks' Law

Schedule Compression is the practice of reducing the planned project duration to deliver software earlier than the estimated schedule.

- Brooks' Law states that adding more people to a late software project makes it later because communication, coordination, and training overhead increase.
- **Staffing Curve:** Teams should start small (initial design), peak during coding/testing, and scale down during deployment. Rapid early staffing spikes correlate with project delays.
